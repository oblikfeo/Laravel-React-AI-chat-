# Журнал проекта Uncensia

Краткая история решений, чтобы не пересказывать задачу заново. Обновляется по ходу работы.

## 2026-09-21 — старт проекта

### Что это за проект
Uncensia — сервис по подписке на нейросети. Фишка/УТП: **безцензурные модели**.
Слоган с референса: *"The universe has no restrictions. Neither should AI."*

### Структура папок в этой директории (`Minsk/`)
- `server/` — сам код проекта (Laravel + React + Inertia). Понятное имя = код сервера.
- `docs/` — рабочая документация, этот журнал, заметки.
- `credentials/` — любые доступы/ключи, которые упоминаются в переписке. **Не коммитить в git**, если/когда появится репозиторий.
- `assets/reference/` — вложения от заказчика (скриншоты, макеты, референсы).

### Референс дизайна
- Файл: `assets/reference/uncensia-homepage-reference.png` — макет главной страницы, взятый как есть (тексты, кнопки, центральная часть).
- Что на скриншоте (тёмная тема):
  - Логотип "Uncensia" сверху слева, узкий боковой сайдбар-меню (иконки: new chat/+, поиск, чат, изображения, видео, таблица/grid, профиль, книга, история/waveform, папка).
  - Справа сверху — переключатель светлой/тёмной темы (луна/солнце).
  - По центру — заголовок "uncensia" крупным лого-шрифтом, подзаголовок-слоган, большое поле ввода "Generate or animate videos..." с кнопкой "+", селектором "Public", иконкой микрофона и кнопкой отправки (стрелка вверх).

### Стек
- **Backend:** Laravel
- **Frontend:** React через **InertiaJS**
- Строго следуем принципам Laravel: **1 контроллер = 1 действие** (single-action controllers), никакого "God-контроллера" и мусорного кода.
- На старте — **только фронтенд** (локально, без реальной бэкенд-логики). Бэкенд будет добавляться позже кусками — конкретными функциями по мере необходимости.
- Цель первого этапа: фронтенд, максимально похожий на референс, с рабочими кликами (роутинг между "страницами"/разделами через Inertia, переключение темы и т.п. на моках).

Использует `cmdk`-стиль Command Dialog для поиска (Ctrl+K).
- **UI-киты**: полный набор shadcn-стиля компонентов (button, dialog, alert-dialog, dropdown-menu, select, sheet, sidebar, switch, textarea, tooltip, scroll-area, avatar, command, input-group) — хороший референс структуры компонентов, если будем ставить shadcn/ui у себя.
- Идея по инпуту чата — `ai-chat-input.tsx` с поддержкой распознавания речи (`use-speech-recognition.ts`) — может пригодиться для будущего поля ввода промпта.

### Что осталось / известные ограничения
- Фон — не настоящее видео, а CSS/SVG-имитация. Как только заказчик пришлёт видео-файлы или более точный референс анимации (по типу venice.ai), нужно будет заменить содержимое `AnimatedBackground.jsx` на `<video>`-теги (структура компонента уже готова под это).
- Аутентификация (Breeze login/register) стоит "из коробки", но в структуре сайдбара/дизайна под неё пока не подведён отдельный UI по референсу — заказчик давал скриншот только главной страницы.
- Бэкенд-логика (реальная генерация видео/изображений, реальный чат) не реализована — по договорённости, сейчас только фронтенд с заглушками, бэкенд будет добавляться функциями по мере необходимости.
- Библиотека shadcnspace.com не подключена — доступа/токена нет, и пока свёрстано на чистом Tailwind + lucide-react без неё. Если понадобится — можно подключить позже.

### Договорённости по стилю работы
- Вести журнал кратко, но регулярно — чтобы не пересказывать задачу по 10 раз.
- Все доступы, упомянутые в переписке, фиксировать в `credentials/`.
- Все присланные вложения — в `assets/`, с понятной структурой подпапок.
- Сам код сервера — в отдельной, понятно названной папке (`server/`), не мешать с документацией/ассетами.
- Код Laravel писать строго по конвенциям: 1 контроллер = 1 действие, никакого нагромождения логики.

## 2026-09-22 — фронтенд по макетам + бэкенд

### Материалы
Заказчик прислал папку `figma/`: фон `fon.png`, десктоп со свёрнутым и развёрнутым меню, мобильные главная и меню. Фон скопирован в `server/public/images/space-bg.png`.

Дизайн-система записана отдельно: `docs/DESIGN-SYSTEM.md`. На неё опираемся при отрисовке всех новых страниц.

### Часть 1. Фронтенд

Фон заменён на фотографию из макета вместо прежней CSS-имитации. Картинка одна на обе темы, в светлой поверх неё кладётся вуаль.

Собрано по макетам:
- Сайдбар в двух состояниях: свёрнутый 72px (иконки) и развёрнутый 280px (подписи, Pro-баннер, блок пользователя). Состояние запоминается.
- Все десять пунктов меню в порядке макета: Search, Chat, Agentic Chat, Studio, Feed, Characters, Stories, Personas, Projects плюс кнопка New chat.
- Мобильное меню — полноэкранный оверлей с крестиком, те же пункты.
- Переключатель темы — капсула с двумя иконками.
- Поле ввода, быстрые действия, логотип и слоган — тексты один в один с макета.

Тёмная тема теперь по умолчанию независимо от настроек системы: так первый заход выглядит как задумано в дизайне.

Светлая тема сделана переопределением токенов в `app.css`, а не дублированием классов в компонентах. Новые страницы подхватят её автоматически.

### Часть 2. Бэкенд

**а) Авторизация.** Одна страница `/auth`, три формы переключаются на клиенте без перезагрузки. Регистрация строго в три поля: имя, почта, пароль, без подтверждений. Восстановление пароля только сверстано, SMTP не подключён. Контроллеры раздельные: показ страницы, вход, регистрация, выход.

**б) Хранение чатов.** Две таблицы: `chats` и `messages`. У чата есть поле `last_message_at` — денормализованная метка, позволяющая сортировать список без соединения с таблицей сообщений. У сообщения есть роль `user` или `assistant`. Доступ закрыт политикой: чужой чат отдаёт 403. Схема намеренно простая, без лишних сущностей.

**в) Подключение модели.** Работа с AI вынесена в сервис с интерфейсом и двумя реализациями. Пока ключ не задан, отвечает заглушка с пояснением — интерфейс проверяется без ключа и без оплаты. Как только ключ появляется в `.env`, автоматически подставляется реальный провайдер. Формат запроса совместим с OpenAI, поэтому OpenRouter, Ollama и OpenAI переключаются одной строкой конфигурации. Сбой провайдера не роняет диалог: вопрос сохраняется, вместо ответа показывается пояснение.

Чтобы включить реальные ответы, нужен бесплатный ключ с openrouter.ai, он выдаётся без привязки карты. Ключ вставляется в `.env` в переменную `OPENROUTER_API_KEY`.

**г) Режим диалога.** Лента сообщений с полем ввода снизу. Вопрос пользователя показывается сразу, под ним индикатор набора, поэтому ожидание не выглядит зависанием. Ответ модели рисуется во всю ширину со значком, вопрос — пузырём справа.

### Проверки
Написано 17 тестов, все проходят: регистрация и её валидация, вход и защита от перебора, создание чата с ответом модели, запрет доступа к чужому чату, редирект гостя, поведение провайдера при успехе и при сбое.

Вёрстка сверена с макетами через скриншоты в реальном браузере. По ходу найдены и исправлены три настоящие ошибки: страница диалога падала из-за обёртки ресурсов Laravel в ключ `data`, светлая тема перекрывала фон целиком, мобильное меню просвечивало.

### Что осталось
- Пункты меню кроме Chat ведут на несуществующие адреса — страницы ещё не нарисованы.
- Кнопки внутри поля ввода: прикрепление файла, голосовой ввод, Public/Private пока не подключены к логике.
- Восстановление пароля ждёт настройки почты.
- Ответы приходят целиком, без посимвольного вывода. Потоковый вывод можно добавить позже.
- Vite требует Node 20.19+, установлена 20.11. Горячая перезагрузка не работает, после правок фронтенда нужен `npm run build`.

## 2026-09-22 (продолжение) — английский интерфейс и правила вёрстки

### Язык
Весь текст, который видит пользователь, переведён на английский: подписи полей, кнопки, плейсхолдеры, заголовки вкладок, служебные подписи вроде «Recent», сообщения валидации на бэкенде и текст демо-ответа модели.

Комментарии в коде и эта документация остались на русском — их читает команда, а не пользователь. Правило записано в дизайн-системе, раздел «Язык интерфейса», вместе с таблицей типовых формулировок, чтобы «Sign in» и «Log in» не начали гулять по страницам.

### Выравнивание кнопки
Проблема со скрина подтвердилась: текст в кнопке был смещён вправо. Причина не в стилях, а в разметке. Содержимое передавалось выражением с переносами строк, React превращал переносы в пробельные узлы, и в блочной кнопке они сдвигали текст вбок.

Починено переводом кнопки на flex с центрированием. Правило вынесено в дизайн-систему отдельным разделом: любые элементы с содержимым по центру выравниваем через flex, а не через text-align.

### Стандарт отступов
Записан в дизайн-систему. Базовый шаг 4 пикселя, все значения кратны ему. Главное правило: расстояние внутри смысловой группы всегда меньше, чем между группами. Раньше метка отстояла от своего поля почти так же, как поля друг от друга, из-за чего форма читалась рвано.

Приведены к стандарту карточка входа и все три формы.

### Попутно найдено
Значок логотипа терял заливку, когда появлялся на странице дважды: идентификатор градиента был жёстко задан, и второй экземпляр ссылался на тот же. Идентификатор сделан уникальным для каждого экземпляра.

Расхождение документации с кодом: в дизайн-системе для пункта Feed была указана иконка LayoutGrid, хотя в коде уже стоит Table2. Документация исправлена.

### Проверки
17 тестов проходят. Формы, главная, диалог и мобильное меню сверены скриншотами в браузере.

## 2026-09-22 (продолжение) — боевой сервер и репозиторий

История разбита на осмысленные коммиты, а не залита одной кучей: документация, каркас, хранение чатов, подключение модели, маршруты, интерфейс, тесты, развёртывание. По каждому написано, что сделано и почему принято именно такое решение.

### Боевой сервер
Приложение работает: http://154.41.135.175

Сервер настроен с нуля. Поставлены PHP 8.3, PostgreSQL 14, Nginx, Node 22, Composer.

Отличия от локальной среды, о которых стоит помнить:
- PHP 8.3 вместо 8.2. Свежая поддерживаемая версия, приложение совместимо с обеими.
- PostgreSQL вместо SQLite. Пароль базы генерируется на сервере и лежит только там, в переписку не передавался.
- Node 22, поэтому на сервере сборка идёт без предупреждений, в отличие от локальной машины.

Настроена безопасность: файрвол пропускает только SSH и веб, база слушает только локальный адрес, отладочный режим выключен, `.env` закрыт от посторонних, добавлен вход по SSH-ключу.

Полный сценарий проверен прямо на боевом: регистрация, создание чата, ответ модели.

### Выкатка
Скрипт `scripts/deploy.sh`. Запускается одной командой с вашей машины, забирает свежий код, ставит зависимости, собирает фронтенд, применяет миграции, обновляет кеши и проверяет, что главная отвечает. Повторный запуск безопасен.

Подробности в `docs/DEPLOY.md`.

### Локальная работа только с фронтендом
Раньше для проверки вёрстки приходилось поднимать бэкенд у себя. Теперь есть команда `npm run preview`: она поднимает лёгкий сервер, который отдаёт вашу локальную сборку, а все запросы проксирует на боевой. Интерфейс смотрится с настоящими данными, PHP и база локально не нужны.

Две тонкости, которые пришлось учесть. Боевой сервер проставляет в разметке свои абсолютные адреса, поэтому в проксируемом HTML и в заголовках перенаправления они переписываются на локальные. Без этого браузер грузил бы сборку с сервера, и локальные правки вёрстки были бы не видны.

Команда `npm run watch` пересобирает фронтенд при каждом изменении файла — частичная замена горячей перезагрузке, которая на Node 20.11 не работает.

### Что стоит сделать дальше
- Сменить пароль root: он приходил открытым текстом в переписке
- Отключить вход по паролю, оставив только ключ
- Подключить домен и сертификат, пока сайт работает по HTTP
- Настроить автоматические резервные копии базы до появления настоящих пользователей
- Вставить ключ OpenRouter, чтобы включить настоящие ответы модели

## 2026-09-22 (продолжение) — MVP: интерфейс без внутренностей, модель, HTTPS

### Главное правило
Боевой сервер теперь MVP, который смотрят люди. **Внутренняя кухня в интерфейс не попадает никогда.**

Раньше при отсутствии ключа пользователю показывался текст с именем переменной окружения, названием сервиса и инструкцией для разработчика, а под каждым ответом стояло название модели. Это исправлено: теперь в любой нештатной ситуации человек видит одну короткую фразу обычным языком, а причина уходит в лог.

Правило записано в дизайн-систему со списком того, что не показывается никогда: имена переменных и файлов настроек, названия сервисов, библиотек и моделей, инструкции разработчику, слова «демо», «заглушка», «тест», коды ошибок и куски трассировки.

На это добавлен тест: он проверяет, что запасной ответ не содержит ни одного из запретных слов. Случайно вернуть такой текст уже не получится.

### Подключена модель
Ключ OpenRouter вставлен на сервер, модель отвечает по-настоящему.

Взята бесплатная `liquid/lfm-2.5-2.6b:free`, расход по ключу нулевой. По ходу выяснилось, что часть бесплатных моделей нерабочие: обе модели Gemma возвращают ошибку провайдера. Проверенные рабочие варианты перечислены в `credentials/ACCESS.md`.

Попутно всплыли две вещи в самом провайдере. Некоторые сервисы отвечают кодом 200 и кладут ошибку внутрь тела — теперь это ловится. Рассуждающие модели тратят лимит на размышления и возвращают пустой ответ, поэтому добавлен разумный лимит длины и запасное чтение поля с рассуждениями.

### HTTPS
Сайт работает по защищённому соединению: **https://154-41-135-175.sslip.io**

Сертификат Let's Encrypt, продлевается сам, действует до 21 декабря.

Своего домена нет, а на голый адрес сертификат не выдают. Взят `sslip.io` — бесплатный сервис, отдающий адрес прямо из имени, поэтому сертификат настоящий и браузер не ругается. Решение временное, при появлении домена меняется одной командой.

Три вещи, которые пришлось починить по ходу:
- certbot переадресовывал на HTTPS только запросы по имени, а заход по адресу из переписки отдавал 404. Теперь любой заход ведёт на защищённое соединение.
- HTTP/2 не включался: на сервере Nginx 1.18, а свежий синтаксис директивы появился в 1.25. Конфигурация не применялась, сайт при этом работал на старой.
- Приложению добавлено доверие к заголовкам Nginx, иначе Laravel считал соединение незащищённым и строил ссылки по http.

Проверка в скрипте выкатки тоже поправлена: она обращалась по http и принимала правильную переадресацию за сбой.

### Что осталось
- Сменить пароль root и ключ OpenRouter: оба приходили открытым текстом
- Отключить вход по паролю в настройках SSH
- Подключить свой домен вместо временного имени
- Настроить автоматические резервные копии базы

## 22 сентября 2026

### Читаемость ответов модели
Ответ лежал прямо на фоне, а фон — фотография со свечением планеты, на
которой белый текст терялся. Под ответ добавлена затемнённая стеклянная
подложка в том же стиле, что остальные поверхности макета.

Насыщенность подобрана по самому светлому участку фона: при 45% нижние
строки длинного ответа всё ещё бледнели, остановились на 70%. Пузырь
пользователя оставлен светлым, чтобы стороны диалога различались с
первого взгляда. Правило записано в дизайн-систему, §16.

### Найдено: режим просмотра не показывал правки
Проверяя подложку скриншотом, обнаружил, что она не появляется, хотя
класс в сборке есть. Причина: разметку отдаёт боевой сервер, и в ней
стоят имена файлов сборки с его хешами. Локальная сборка даёт другие
хеши, таких файлов в `public/` нет, и запрос уходил обратно на сервер.

То есть `npm run preview` всё это время показывал боевой сайт, а не
локальные изменения: правка становилась видна только после выкатки.
Режим просмотра теперь подменяет имена файлов на локальные из манифеста.

### Светлая тема
При проверке подложки в светлой теме ответ оказался нечитаем: белый
текст на белой подложке. Причина — текст был переведён на `text-white/95`,
а переопределения цвета для этой прозрачности в светлой теме не было,
он и остался белым. Добавлено; подложка ответа сделана плотнее
остальных поверхностей, иначе сквозь неё пробивается свечение.

Замечено попутно: в светлой теме так же нечитаемы сайдбар и пузырь
пользователя. Дефект существовал до этой правки, к подложке отношения
не имеет. Не чинил, чтобы не смешивать с текущей задачей.
