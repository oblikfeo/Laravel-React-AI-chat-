## Выкатка изменений

После того как изменения отправлены в `main` на GitHub, выкатка делается одной командой с вашей машины:

```bash
ssh -i credentials/ssh/uncensia_deploy root@154.41.135.175 \
    'bash /var/www/uncensia/scripts/deploy.sh'
```

Скрипт забирает свежий код, ставит зависимости, собирает фронтенд, применяет миграции, обновляет права и кеши, перезапускает PHP и проверяет, что главная отвечает. Запускать его повторно безопасно.

Если проверка в конце не прошла, скрипт покажет код ответа и подскажет, где смотреть логи.

## Модель

Ключ подключён, модель отвечает. Используется `liquid/lfm-2.5-2.6b:free` — бесплатная, расход по ключу нулевой.

Сменить модель можно переменной `OPENROUTER_MODEL` в `.env`, код править не нужно. После правки обязательно `php artisan config:cache`.

Не все бесплатные модели рабочие: часть возвращает ошибку провайдера. Проверенные варианты перечислены в `credentials/ACCESS.md`.

Если ответы перестанут приходить, смотрите лог приложения: причина пишется туда, а пользователю показывается нейтральное сообщение.

### Как сменить ключ

1. Новый ключ берётся на https://openrouter.ai/keys
2. Впишите его на сервере:

```bash
ssh -i credentials/ssh/uncensia_deploy root@154.41.135.175
nano /var/www/uncensia/server/.env
```

Найдите строку `OPENROUTER_API_KEY=` и добавьте ключ после знака равенства.

3. Обновите кеш настроек, иначе приложение продолжит читать старое значение:

```bash
cd /var/www/uncensia/server && php artisan config:cache
```

Провайдера можно сменить на другой, совместимый с форматом OpenAI, например на Ollama или сам OpenAI. Для этого меняется переменная `AI_PROVIDER`, варианты перечислены в `server/config/ai.php`.

## Безопасность

Сделано:

- Файрвол пропускает только SSH, HTTP и HTTPS
- База доступна только с самого сервера
- Файл `.env` читается только владельцем и веб-сервером
- Отладочный режим выключен, ошибки не показываются посетителям
- Вход по SSH-ключу настроен

HTTPS включён. Сертификат Let's Encrypt на имя `154-41-135-175.sslip.io`, продлевается сам. Любой заход по HTTP переадресуется на защищённое соединение, браузеру отправляется заголовок, запрещающий возврат на HTTP.

Про имя: `sslip.io` — бесплатный сервис, который отдаёт адрес прямо из имени, поэтому на него можно выпустить настоящий сертификат. Это временное решение, пока нет своего домена. Когда домен появится, порядок такой:

```bash
certbot --nginx -d ваш-домен.com --redirect
```

Затем поправить `APP_URL` в `.env` и выполнить `php artisan config:cache`.

Осталось сделать:

- Сменить пароль root, он приходил открытым текстом
- Отключить вход по паролю в настройках SSH
- Подключить свой домен вместо временного имени
- Настроить автоматические резервные копии



## Приём платежей

Логика подписок написана и работает, платёжная система не подключена.
Пока реквизиты не заданы, кнопки тарифов показывают «Coming soon».

### Как включить приём денег (ЮKassa)

1. Возьмите в личном кабинете ЮKassa номер магазина и секретный ключ.
2. Впишите их в `.env` на сервере:

```
YOOKASSA_SHOP_ID=номер-магазина
YOOKASSA_SECRET_KEY=секретный-ключ
```

3. Обновите кеш настроек:

```bash
cd /var/www/uncensia/server && php artisan config:cache
```

4. В кабинете ЮKassa укажите адрес для уведомлений:

```
https://154-41-135-175.sslip.io/billing/webhook
```

Больше ничего менять не нужно: код готов, кнопки тарифов заработают сами.

### Что уже учтено

- Повторное уведомление не продлевает подписку дважды
- Подлинность уведомления проверяется обращением к ЮKassa, а не
  доверием к содержимому запроса
- Суммы хранятся в копейках
- Отменённая подписка работает до конца оплаченного срока
- Просроченные подписки переводятся на бесплатный тариф ежечасно

### Проверка расписания

Команда `subscriptions:expire` должна выполняться по расписанию.
Проверить, что планировщик запущен:

```bash
crontab -l | grep schedule:run
```

Если строки нет, добавьте:

```
* * * * * cd /var/www/uncensia/server && php artisan schedule:run >> /dev/null 2>&1
```

## Вход через Google

Код готов целиком. Чтобы включить, нужны два значения из Google Cloud
Console.

1. Создайте проект на https://console.cloud.google.com
2. Раздел «APIs & Services» → «Credentials» → «Create credentials» →
   «OAuth client ID», тип «Web application»
3. В «Authorized redirect URIs» добавьте:

```
https://154-41-135-175.sslip.io/auth/google/callback
```

4. Полученные значения впишите в `.env` на сервере:

```
GOOGLE_CLIENT_ID=идентификатор
GOOGLE_CLIENT_SECRET=секрет
GOOGLE_REDIRECT_URI=https://154-41-135-175.sslip.io/auth/google/callback
```

5. Обновите кеш настроек:

```bash
cd /var/www/uncensia/server && php artisan config:cache
```

Кнопка входа появится сама. Пока ключей нет, она скрыта: вести на
страницу, которая ответит ошибкой, нельзя.

## Посетители без учётной записи

Чат работает без регистрации: одна модель и десять сообщений в день.
Настраивается в `.env`:

```
GUEST_DAILY_MESSAGES=10          # сообщений в день на посетителя
GUEST_DAILY_MESSAGES_PER_IP=50   # потолок на один адрес
GUEST_MODEL=auto                 # какая модель доступна
GUESTS_ENABLED=true              # выключает гостевой режим целиком
```

Посетитель узнаётся по куке (живёт год), а при её потере — по
отпечатку браузера.

**Про IP.** Он намеренно не используется для опознания: за одним
адресом сидит весь дом, офис или кофейня, а у мобильных операторов —
тысячи абонентов. Считать их одним человеком значит выдать десять
сообщений на весь дом. IP применяется только как потолок с адреса —
защита от накрутки через режим инкогнито.

Переписка переходит в учётную запись при регистрации и при входе.

## Студия: генерация изображений

Код готов целиком. Генерация выключена, потому что провайдер не
открыл доступ к моделям изображений — не из-за настроек с нашей
стороны.

### Что проверено

Ключ рабочий, денег на нём почти вся сумма, текстовые модели отвечают.
Все шесть моделей генерации изображений возвращают отказ:

```
403 The request is prohibited due to a violation of provider Terms Of Service
```

Отказ приходит на любой запрос, включая безобидный «red cube», то есть
дело не в том, что мы просим нарисовать.

### Как включить, когда доступ появится

1. Убедитесь, что запрос к модели изображений проходит:

```bash
curl -X POST https://openrouter.ai/api/v1/chat/completions \
  -H "Authorization: Bearer $OPENROUTER_API_KEY" \
  -H "Content-Type: application/json" \
  -d '{"model":"google/gemini-3.1-flash-lite-image",
       "messages":[{"role":"user","content":"red cube"}],
       "modalities":["image","text"]}'
```

2. Впишите в `.env` на сервере:

```
STUDIO_ENABLED=true
```

3. Обновите кеш настроек:

```bash
cd /var/www/uncensia/server && php artisan config:cache
```

Больше ничего менять не нужно: форма и лента заработают сами.

### Настройки

```
STUDIO_ENABLED=false       # включает генерацию
STUDIO_GUEST_DAILY=3       # работ в день у гостя
STUDIO_FREE_DAILY=15       # работ в день на бесплатном тарифе
STUDIO_DEFAULT_MODEL=flash # модель по умолчанию
STUDIO_TIMEOUT=180         # сколько ждём картинку, секунд
```

Модели, соотношения сторон и стили перечислены в `config/studio.php`:
добавить новый вариант — это одна запись в массиве.

### Хранение

Изображения лежат в `storage/app/private/studio/`, разложены по
владельцам. В публичную папку не попадают: файл отдаётся через
приложение с проверкой владельца, чужую работу открыть нельзя.

**Про место на диске.** Изображения занимают заметно больше текста.
На сервере 100 ГБ — этого хватит на старт, но к запуску стоит решить,
переезжаем ли на внешнее хранилище, и настроить удаление старых работ
у гостей.

## Студия

Генерация работает через Venice AI — тот самый сервис, который мы
берём за образец. Один ключ закрывает весь раздел: рисование, правку,
увеличение, удаление фона и озвучку.

Через OpenRouter генерация картинок недоступна: он отвечает отказом на
все модели изображений. Разбор — в docs/STUDIO-API.md.

Что нужно:

1. Купить ключ на https://venice.ai → Settings → API Keys. Нужен тариф
   с пополняемым балансом, а не подписка на сайт: подписка даёт доступ
   к интерфейсу Venice, а не к API.
2. Положить в `.env` на сервере:

```
VENICE_API_KEY=<ключ>
```

3. Применить: `php artisan config:cache`.

Пока ключа нет, раздел открывается и показывает, что скоро заработает:
формы видны, кнопки заблокированы, ошибок на экране нет.

Проверка после подключения:

```bash
curl -s https://api.venice.ai/api/v1/models?type=image   -H "Authorization: Bearer $VENICE_API_KEY" | head -c 200
```

Цены из каталога провайдера: рисование 0.01–0.10 $ за картинку,
увеличение 0.02–0.08 $, озвучка дешевле. Остаток виден по
`GET /billing/balance`.
