## Выкатка изменений

После того как изменения отправлены в `main` на GitHub, выкатка делается одной командой с вашей машины:

```bash
ssh -i credentials/ssh/uncensia_deploy root@154.41.135.175 \
    'bash /var/www/uncensia/scripts/deploy.sh'
```

Скрипт забирает свежий код, ставит зависимости, собирает фронтенд, применяет миграции, обновляет права и кеши, перезапускает PHP и проверяет, что главная отвечает. Запускать его повторно безопасно.

Если проверка в конце не прошла, скрипт покажет код ответа и подскажет, где смотреть логи.

## Модель

Ключ подключён, модель отвечает. Используется `liquid/lfm-2.5-2.6b:free` — бесплатная, расход по ключу нулевой.

Сменить модель можно переменной `OPENROUTER_MODEL` в `.env`, код править не нужно. После правки обязательно `php artisan config:cache`.

Не все бесплатные модели рабочие: часть возвращает ошибку провайдера. Проверенные варианты перечислены в `credentials/ACCESS.md`.

Если ответы перестанут приходить, смотрите лог приложения: причина пишется туда, а пользователю показывается нейтральное сообщение.

### Как сменить ключ

1. Новый ключ берётся на https://openrouter.ai/keys
2. Впишите его на сервере:

```bash
ssh -i credentials/ssh/uncensia_deploy root@154.41.135.175
nano /var/www/uncensia/server/.env
```

Найдите строку `OPENROUTER_API_KEY=` и добавьте ключ после знака равенства.

3. Обновите кеш настроек, иначе приложение продолжит читать старое значение:

```bash
cd /var/www/uncensia/server && php artisan config:cache
```

Провайдера можно сменить на другой, совместимый с форматом OpenAI, например на Ollama или сам OpenAI. Для этого меняется переменная `AI_PROVIDER`, варианты перечислены в `server/config/ai.php`.

## База данных

PostgreSQL, база и пользователь называются `uncensia`. Пароль создан прямо на сервере при настройке и лежит в `/root/.uncensia/db_password` с доступом только для root. В переписке он не передавался.

База слушает только локальный адрес и снаружи недоступна.

Посмотреть данные:

```bash
cd /var/www/uncensia/server && php artisan tinker
```

Резервная копия:

```bash
sudo -u postgres pg_dump uncensia > /root/uncensia-$(date +%F).sql
```

Автоматическое резервное копирование пока не настроено. Стоит сделать до того, как появятся настоящие пользователи.

## Безопасность

Сделано:

- Файрвол пропускает только SSH, HTTP и HTTPS
- База доступна только с самого сервера
- Файл `.env` читается только владельцем и веб-сервером
- Отладочный режим выключен, ошибки не показываются посетителям
- Вход по SSH-ключу настроен

HTTPS включён. Сертификат Let's Encrypt на имя `154-41-135-175.sslip.io`, продлевается сам. Любой заход по HTTP переадресуется на защищённое соединение, браузеру отправляется заголовок, запрещающий возврат на HTTP.

Про имя: `sslip.io` — бесплатный сервис, который отдаёт адрес прямо из имени, поэтому на него можно выпустить настоящий сертификат. Это временное решение, пока нет своего домена. Когда домен появится, порядок такой:

```bash
certbot --nginx -d ваш-домен.com --redirect
```

Затем поправить `APP_URL` в `.env` и выполнить `php artisan config:cache`.

Осталось сделать:

- Сменить пароль root, он приходил открытым текстом
- Отключить вход по паролю в настройках SSH
- Подключить свой домен вместо временного имени
- Настроить автоматические резервные копии

## Если что-то сломалось

Посмотреть последние ошибки приложения:

```bash
tail -50 /var/www/uncensia/server/storage/logs/laravel.log
```

Посмотреть ошибки веб-сервера:

```bash
tail -50 /var/log/nginx/error.log
```

Проверить, что службы живы:

```bash
systemctl status nginx php8.3-fpm postgresql --no-pager
```

Частая причина странного поведения после изменения `.env` — старый кеш настроек. Лечится так:

```bash
cd /var/www/uncensia/server && php artisan config:cache
```
